# Professional GitHub Setup — Rahna Rasool

This folder contains:
- `README.md` — a profile README template for your GitHub profile.
- `dashboard/index.html` — a responsive developer dashboard website.
- `dashboard/style.css` — purple-gradient styling and mobile layouts.
- `dashboard/script.js` — small interactions (theme toggle and current year).

## 1. Personalize your GitHub profile

1. Sign in to GitHub and create a **public repository with exactly the same name as your GitHub username**.
2. Add the `README.md` file from this folder to that repository.
3. Replace every placeholder:
   - `YOUR_GITHUB_USERNAME`
   - `YOUR_EMAIL_ADDRESS`
   - `YOUR_LINKEDIN_PROFILE`
   - `ADD_TECHNOLOGIES`
   - `ADD_REPOSITORY_LINK`
4. Commit the file. GitHub will display the README on your profile page.

## 2. Run the dashboard website

1. Open the `dashboard` folder.
2. Double-click `index.html` to preview it in your browser.
3. Replace `YOUR_GITHUB_USERNAME` in `index.html` with your actual username.
4. Update project descriptions, skill bars, LinkedIn link, and project repository URLs to reflect your real experience.

The website uses Google Fonts when online; the layout and content remain usable if those fonts do not load.

## 3. Publish the dashboard with GitHub Pages

1. Create a new GitHub repository, for example `rahna-developer-dashboard`.
2. Upload the three files from the `dashboard` folder (`index.html`, `style.css`, `script.js`) to the repository root.
3. Open **Settings → Pages** in that repository.
4. Under **Build and deployment**, choose **Deploy from a branch**.
5. Select your default branch (often `main`) and folder `/ (root)`, then save.
6. Wait for GitHub Pages to publish your site. The Pages section will show the published URL.

## Before sharing

- Change all placeholders and test every link.
- Only list skills and technologies you have actually used; the skill levels shown on the demo website are examples.
- The project cards are editable examples, not claims that these repositories already exist.
- Do not put passwords, access tokens, or other secrets in public repositories.
